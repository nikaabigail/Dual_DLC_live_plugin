# Экспериментальная медленная обработка колена

Этот каталог содержит отдельные офлайн-прототипы. Они **не подключены к live-плагину**, не меняют его быстрые триггеры и не управляют стимуляцией. Python 3.10+ и NumPy; GPU, Torch, DLC, камеры и реальные данные для запуска не нужны.

## rc3: поправка по текущему кадру

Для новой геометрической обработки используется `current_frame_knee.py`. Он принимает hip/knee/ankle выбранной стороны, их исходную уверенность, nose или глаз той же стороны и явную калибровку. Чистый расчёт использует только стандартную библиотеку; NumPy нужен инструментам чтения сохранённых массивов и прежней медленной обработке.

Две окружности задают кандидатов колена. Ветвь выбирается прежним правилом `canonical_branch_sign × heading`, где знак сгиба установлен при калибровке, а направление тела получено из текущего кадра. Никакого подбора радиусов по текущему предсказанному колену нет.

При исходной уверенности knee/hip/ankle не ниже 0,6 выполняется мягкое смешивание: `K = K_DLC + (K_geometry - K_DLC) × 0.25 / (clip(p_knee, 0.2, 1) + 0.25)`. Сдвиг ограничен `0.15 × (F + T)`; расхождение источников более `0.5 × (F + T)` отключает поправку. При недостоверных опорах, отсутствии направления, несовместимых окружностях или неподходящей ветви сохраняется исходная точка со статусом отказа. Отсутствующее/низкоуверенное колено не дорисовывается. Возвращённый `likelihood` — исходная метаданная DLC, а не уверенность исправленного колена.

**Нет буфера, интерполяции, сглаживания координат и ожидания будущих кадров.** Другие ориентиры не меняются. Калибровка отсутствует — возвращается raw со статусом `raw_missing_calibration`. Веса/размеры конкретной крысы по умолчанию не встроены.

Пример API с вымышленными числами (не профиль для животных):

```python
from experiments.knee_slow_loop.current_frame_knee import CircleCalibration, fuse_current_frame

calibration = CircleCalibration(
    width=1920, height=220, femur_px=80.0, tibia_px=70.0,
    canonical_branch_sign=-1, calibration_id="synthetic-example",
)
result = fuse_current_frame(
    hip=(900, 40, 0.9), knee=(960, 100, 0.8), ankle=(900, 150, 0.9),
    nose=(1100, 70, 0.9), calibration=calibration,
)
print(result.fused_xy, result.status)
```

Калибровка должна соответствовать животному, камере, масштабу и системе координат. Передаются **итоговые проекционные длины**: если при подготовке радиусов уже применена анатомическая поправка, модуль не применяет её второй раз. Литературное отношение длин костей не является готовой калибровкой пиксельных сегментов.

`run_current_frame.py --help` описывает запуск по сохранённому NPZ без загрузки модели. Сторона передаётся явно или читается из прежнего native replay с исходным `python_route`; не выбирается заново по визуальной маске. `synthetic_calibration.json` — шаблон, не рабочая калибровка: SHA входного NPZ и параметры требуется задать для своей записи. CLI проверяет привязку к данным, размер кадра и систему координат. В Git не включены реальные радиусы/исходные аннотации сравнения №13.

Пример команды из корня репозитория с подготовленной собственной калибровкой:

```sh
python experiments/knee_slow_loop/run_current_frame.py --poses raw_roi_poses.npz --calibration calibration.json --native-replay native_filtered.jsonl --width 1920 --height 220 --coordinate-context full_frame_pixels_top_left --output out/current_frame_knee
```

Если NPZ уже содержит `selected_side` или `side`, `--native-replay` не нужен. Для отдельного файла сторон есть `--sides` с обязательным совпадением `frame_index`. Размеры и контекст можно хранить в метаданных NPZ вместо аргументов. Сохранённые результаты — `correction.npz` и `compute_summary.json`; повторная запись требует явного `--overwrite`.

На полном ролике №13 перенос метода проверяется отдельно относительно сохранённого одобренного результата, с прежними радиусами для каждого кадра и историческим leave-one-out. Обычная фиксированная калибровка CLI не подменяется этими специфичными для записи исключениями. [Проверка rc3 и ограничения](../../docs/VALIDATION_2026_10_14.md).

## Прежнее сглаживание: отдельный временной интерфейс

Из корня репозитория:

```sh
python -m pip install -r experiments/knee_slow_loop/requirements.txt
python -m unittest discover -s experiments/knee_slow_loop -v
python experiments/knee_slow_loop/simulation.py --output-dir out/knee_slow_loop
```

Последняя команда сохраняет синтетические результаты в JSON и CSV. Тесты охватывают новый расчёт текущего кадра, прежнюю численную обработку и дискретную модель очереди.

`streaming_knee.py` принимает готовые координаты hip/knee/ankle и необязательную готовую геометрическую гипотезу с радиусами. Смешивание ограничивает смещение колена, затем сглаживает его относительно бедра в кольцевом буфере максимум из 7 кадров. Обработка возвращает только центральный кадр, когда доступны 3 следующих. Бедро и голеностоп не изменяются. Скорректированной точке не присваивается исходная DLC likelihood как оценка новой уверенности.

Три будущих кадра означают 30 мс при 100 Гц и 60 мс при 50 Гц до остальных задержек. `sample_period_s` и `expected_frame_stride` задают ожидаемую частоту и намеренное прореживание. Неожиданные пропуски кадров или времени, смена стороны, камеры либо версии стимуляции сбрасывают окно. Дубликаты и переставленные кадры отвергаются. Пропуск только точки колена длиной 1–3 кадра восстанавливается, когда обе наблюдаемые границы уже доступны; входные разрывы и длинные пропуски не склеиваются. Неполное окно в конце записи не дополняется.

Временные метки и `now_s` должны относиться к одним монотонным часам. Проверка возраста внутри `push` относится к **началу** вычисления. Владелец worker должен повторно проверить возраст, текущую версию стимуляции и контекст **после** вычисления. Такой live-worker, итоговая проверка пригодности результата, наблюдение за прекращением поступления данных и контроллер стимуляции здесь не реализованы. Ограниченное кольцо также не ограничивает внешнюю очередь вызывающего приложения.

`simulation.py` отдельно моделирует FIFO и один активный расчёт с одним заменяемым ожидающим заданием. В модели есть проверки возраста и контекста на завершении, паузы worker и источника. Порог свежести 150 мс — условие синтетического теста, а не обоснованная физиологическая задержка. Ограничение очереди не гарантирует, что пригодные обновления вообще будут поступать.

В старый `streaming_knee.py` направление тела, построение окружностей, оценка радиусов и дополнительные предсказания головы не входят: геометрия поступает уже вычисленной. Новый `current_frame_knee.py` рассчитывает окружности отдельно и не вызывает этот временной интерфейс. Прототипы не доказывают анатомическую точность, сохранение фаз шага, задержку DLC-инференса или отсутствие конкуренции с GPU. При нерегулярном потоке реальной камеры строгие сбросы временного интерфейса могут уменьшать покрытие — этот режим требует отдельной проверки перед live-интеграцией.

`fixtures/synthetic_offline_fusion.npz` содержит только 80 синтетических входных кадров и зафиксированный независимый эталон прежнего офлайн-алгоритма. Метаданные происхождения, параметры и SHA-256 находятся рядом в JSON. Тест сравнивает полностью наблюдаемые внутренние кадры с этим эталоном; он не пересчитывает ожидаемый ответ через проверяемый streaming-код.
